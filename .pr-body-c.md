# Chore

## Linked issue (required)

Closes #127

## Summary

The adapter is now four packages instead of one, and each one owns its own name, its own entrypoints, its own tests and its own bundle budget.

| package | entrypoints | tag |
| --- | --- | --- |
| `@ailura/nestjs-hono-adapter` (`packages/core`) | `.`, `./bun-server`, `./node-server`, `./fetch` | `v*` |
| `@ailura/nestjs-platform-hono-ws` | `.` | `ws-v*` |
| `@ailura/nestjs-platform-hono-multipart` | `.` | `multipart-v*` |
| `@ailura/nestjs-platform-hono-socket-io` | `.` | `socket-io-v*` |

The repository root is only the private Bun workspace root: no name, no exports, no `src/` shims. **This breaks one published subpath**, and the README carries the migration: `@ailura/nestjs-hono-adapter@1.4.1` published five entrypoints and keeps four of them unchanged; `./ws` moves to `@ailura/nestjs-platform-hono-ws`. `./multipart` and `./socket-io` were added on `main` after 1.4.1 and were never published, so only `./ws` breaks a consumer.

## Changes

- `packages/core` takes the adapter's name and its four entrypoints; the root's `src/` (four re-export shims) is deleted, and so is every publish field the root had.
- The three capabilities become `@ailura/nestjs-platform-hono-{ws,multipart,socket-io}`, one entrypoint each. The compatibility emit goes with the root package: with no root `dist` to emit into, `packages/*/index.ts` and their `tsconfig.compat.json` are gone, and each package's build is a single `tsc` project.
- The bundle budget lives beside the package it gates: `packages/core/.size-limit.json` carries the adapter's four entries and each capability carries its own file, with paths relative to the package. The root `size` script builds and fans out over `./packages/*`, and every package gained a `size` script. No ceiling and no entry name moved.
- Release: `.` leaves `release-please-config.json` and the manifest, the core inherits the `v*` tag shape, the capabilities keep theirs, and `publish.yml` resolves `v*` to `./packages/core`.
- CI and lint drop the dead `src/**` paths; the three guards assert the new contract, and every test lives in the package it tests.
- The upload island still reaches the adapter through one public symbol, `declareMultipart`; the core names none of the three capabilities.

## Verification

- `bun run check` green: lint 0/0, format clean, typecheck, build and the size gate, with **444 tests passing across 47 files** — the 434 baseline plus the eight guards from `2d49de8` plus two new entrypoint-contract tests.
- The size gate runs from the root and fans out: running it inside a package finds that package's file rather than inheriting the root's, and every measurement is unchanged — index 11.53/11.55 kB, bun-server 981 B/1.02 kB, node-server 506/560 B, fetch 496/500 B, multipart 4.2/4.25 kB, ws 1.54/1.55 kB, socket-io 948/950 B.
- `npm pack --dry-run`: the core ships `dist/index.js` plus `dist/servers/{bun,node,fetch}.{js,d.ts}` (201 files); multipart ships `dist/index.js` (111 files).
- The public API is intact, symbol by symbol, against `origin/main`: every entrypoint's exports are identical except one addition, `declareMultipart`, and the three capabilities keep theirs exactly.
- The workspaces are genuine, not aliases: `node_modules/@ailura/*` are symlinks into `packages/`, `bun pm ls` reports them as `@workspace:packages/...`, `import.meta.resolve` reaches each package's own dist, and no manifest or lockfile entry uses `workspace:`, `link:`, `file:` or `npm:` — every dependency is a real range.
- `bun install --frozen-lockfile` passes, so CI installs exactly what the lockfile pins.
- Acceptance criteria of #127: each capability installs independently; the core loads no optional capability and names none; no package exports an internal path; every package is typechecked and tested; CI watches `packages/**`; there is no import change for the four surviving entrypoints; and the dependency graph is in the architecture page.

## Risk / compatibility

- Exactly one published subpath breaks: `./ws`, now its own package. The commit carries a `BREAKING CHANGE` trailer, so release-please cuts the major for `@ailura/nestjs-hono-adapter`.
- The rename reaches beyond #127. It is the human's decision and it sits in the same series; it can be split into its own pull request if you would rather review it apart.
- `bun.lock`'s `""` entry still carries the old root name, stale now that the root has no name. Bun keeps it sticky: regenerating from scratch writes `lockfileVersion: 2`, which the Cloudflare build image and CI reject by policy, and a hand edit is off limits. It is cosmetic — resolution is correct, the core's workspace entry carries the name, and `--frozen-lockfile` passes — but it should be cleared where Bun will rewrite it as version 1.
- The publish order is documented, not enforced: the core must reach npm before multipart, which peers on it. `ws` peers on it optionally and `socket-io` does not name it at all.
- Each package needs its own npm OIDC trusted-publisher entry. The one for `@ailura/nestjs-hono-adapter` keeps working because the name does not move; the three renamed capabilities need new ones.
- Not verifiable from here: release-please cutting the four tags and firing `publish.yml`, and the Nest 11/12 compat matrix that only CI runs.
- Out of scope, left as they were: `docs/bundle-baseline.md` predates the extractions, the README badge still advertises a 10 kB bundle against an 11550-byte ceiling, and `.github/CODEOWNERS` plus `.github/standards.local.yml` name files that live in the organisation standards repository.
