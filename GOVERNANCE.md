# Governance

## Overview

This document describes how the
`@ailuracollective/nestjs-hono-adapter` project makes decisions
and who is responsible for what.

## Roles and Responsibilities

### Maintainers

Maintainers have write access to the repository and are
responsible for:

- Reviewing and merging pull requests
- Triaging issues and pull requests
- Cutting releases
- Enforcing the code of conduct
- Making decisions about the project direction

Current maintainers are listed in [CODEOWNERS](CODEOWNERS).

### Contributors

Anyone can contribute to the project by:

- Opening issues for bugs or feature requests
- Submitting pull requests with code changes
- Participating in discussions
- Improving documentation

### Users

Users of the package can:

- Report bugs and request features
- Ask questions in discussions
- Use the package in their projects under the MIT license

## Decision Making

### Consensus

Decisions are made by consensus among maintainers. When
possible, decisions are made through discussion in issues or
pull requests.

### Voting

If consensus cannot be reached, a decision is made by simple
majority vote of maintainers. Each maintainer gets one vote.

### Final Decision

If the vote is tied, the issue is escalated to the organization
owner (`ailuracollective`) for a final decision.

## Code Review

All code changes must be reviewed by at least one maintainer
before being merged to the main branch. See
[docs/development.md](docs/development.md) for the development
workflow.

## Release Process

Releases are automated through
[semantic-release](https://github.com/semantic-release/semantic-release).
Versions follow [Semantic Versioning](https://semver.org/).

See [docs/development.md](docs/development.md) for details.

## Changing This Document

Changes to this governance document require consensus among all
maintainers and must be made through a pull request.
